# 模板：数据层（HANA + gen-mapper）（data-mapper）

> 面向 HANA 数据访问层：表结构、SQL、MyBatis 生成器、映射、分页。

## 适用 / 不适用

- ✅ HANA 数据访问层：表结构分析、SQL、MyBatis 生成器、映射、分页
- ✅ 需要依据元数据生成 Entity / Mapper 接口 / XML
- ❌ MySQL 或无 `gen-mapper` → `mysql-mapper`
- ❌ 需要改表结构 → 先确认授权，再走 `mysql-mapper` 的 DDL 流程（HANA 侧同样需授权）

## 前置检查（先做，错了会全程卡死）

- [ ] 数据库是 **HANA**，且环境里**确实有 `gen-mapper`**
- [ ] 没有表变更需求（本模板默认**只读**，严禁改表；要 DDL 必须先拿授权）

> 若是 **MySQL** 或没有 `gen-mapper` → 立刻改用 `mysql-mapper`，不要用本模板硬跑。

## 规模

1 架构 + 1 数据库 + 1 开发 + 1 质量（DB 只读阶段串行）。

## 步骤序列

| 步骤 | 角色 | 输入 | 输出 | 写域 |
|------|------|------|------|------|
| 1 | 数据库工程师 | 表名/元数据 | 表结构、字段、索引、约束清单 | 无（只读） |
| 2 | 架构师 | 表结构 + 需求 | 数据访问层设计 + Mapper 方法契约 + 写域 | 无（只读） |
| 3 | 开发 + 数据库 | 契约 + 元数据 | Entity / Mapper 接口 / XML + SQL | 指定包路径 |
| 4 | 质量工程师 | diff + 契约 | 验收（重点 B 层） | 无（只读） |
| 5 | 测试工程师 | 代码 + 契约 | SQL/映射边界用例 + 结果 | 测试目录 |
| 6 | 主 agent / 文档 | 全部结论 | 报告 + 映射说明 | `.team-mode/` |

## 验收重点（B 层强化）

- 字段/类型与元数据一致（给出核对方式，不只说"已核对"）
- SQL 全部 `#{}`，无 `${}`
- 查询有 LIMIT；分页参数化
- MyBatis：resultMap ↔ 实体 ↔ 元数据三方一致
- 关键查询有索引依据（EXPLAIN 或索引清单）
- 无 N+1（集合查询用 IN 批量，调用方判空）

## DoD

- 生成物清单齐全且路径明确
- 映射一致性结论有证据
- 性能风险点已列（不是"无风险"一句话）

## 输出

表结构分析、生成文件清单、映射一致性结论、性能风险与建议。
