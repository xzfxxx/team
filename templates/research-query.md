# 模板：纯查询 / 分析 / 调研（research-query）

> 只查不改、调研、出结论。轻量，多数情况不必开完整团队。

## 适用 / 不适用

- ✅ 回答业务/数据问题、只读查数、技术调研、方案对比、可行性分析
- ❌ 需要改代码 → `standard-dev` / `bugfix-refactor`
- ❌ 要动表或写数据 → 先确认授权，再走数据模板

## 规模

1 角色（主 agent 或架构师）+ 可选 1 数据库；需要复核时再加 1 质量（做结论复核，不写码）。

## 步骤序列

| 步骤 | 角色 | 要点 |
|------|------|------|
| 1 | 架构师 | 拆问题：要回答什么、用什么证据、怎么算验证过 |
| 2 | 数据库工程师（数据相关时） | 只读 SQL，附 SQL 与结果摘要、口径说明 |
| 3 | 主 agent | 汇总结论（**本模板允许主 agent 出结论**，报告里声明这是例外） |
| 4 | 质量工程师（可选） | 独立复核结论与依据是否匹配，专门找"结论大于证据"的地方 |

## 验收重点

- 结论有依据：SQL/文档/代码位置可溯
- 口径写清楚（时间范围、过滤条件、数据版本）
- 区分"已验证"与"推测"；推测必须标注
- 全程无代码改动、无写库

## DoD

- 结论能复现（给出可重跑的查询/命令）
- 边界与反例说明（什么情况下结论不成立）
- 明确列出没查到的部分

## 输出

结论（含依据）、关键 SQL/命令、口径、后续建议。
