# 模板：前端页面 / 组件 / 交互（frontend-page）

> 页面、组件、交互、接口联调。前端工程师为主，必要时拉后端开发联调。

## 适用 / 不适用

- ✅ 新增/修改页面、组件、交互、样式、响应式、可访问性
- ✅ 前端接后端接口、联调
- ❌ 纯样式微调且单文件 → `quick-task`
- ❌ 只排查接口数据问题 → `research-query`

## 规模

1 产品（交互与验收标准）+ 1 前端 + 1 开发（联调时）+ 1 测试 + 1 质量。

## 步骤序列

| 步骤 | 角色 | 输入 | 输出 | 写域 |
|------|------|------|------|------|
| 1 | 产品经理 | 需求/设计稿 | 交互说明 + 验收标准（含空/错/加载态） | 无 |
| 2 | 前端工程师 | 需求 + 接口契约 | 页面/组件实现 + 构建与 lint 输出 | 前端目录 |
| 3 | 开发工程师（如需） | 接口契约 | 接口实现 / mock / 联调结论 | 后端目录 |
| 4 | 测试工程师 | 实现 + 验收标准 | 交互与边界用例 + 结果 | 测试目录 |
| 5 | 质量工程师 | diff + 标准 | 验收（重点 C 层） | 无 |
| 6 | 主 agent | 全部结论 | 报告（附截图路径） | `.team-mode/` |

## 验收重点（C 层）

- 加载 / 空 / 错误三态都有处理，不是只做 happy path
- 接口字段与契约一致，无写死的假字段
- 构建、lint 通过；无 console error（贴输出）
- 响应式断点覆盖；键盘可达、语义标签、对比度达标
- 大列表/频繁交互无明显卡顿（涉及时说明验证方式）

## DoD

- 验收标准逐条对照（不是"看着没问题"）
- 构建/lint 输出可见
- 截图或录屏路径（如可产出）
- 明确"哪些是 mock、哪些接了真实接口"

## 输出

改动文件、功能点与效果说明、证据、遗留问题。
